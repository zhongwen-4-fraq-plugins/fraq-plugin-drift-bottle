# WebUI bottle CRUD boundaries

SUMMARY: WebUI 新增只创建文本瓶子；修改时按原索引更新全部文字段，并始终保留图片、视频、表情和合并转发等非文字消息段。
READ WHEN: before extending WebUI bottle creation, editing, deletion, or message-segment editing

---

- 插件主人和漂流瓶管理员可新增、修改、删除瓶子；前端隐藏无权限操作只是体验优化，写接口必须从服务端会话重新解析账号并检查权限。
- 新增接口接收发送者 QQ、显示名称、会话类型、来源 ID 和最多 500 字符的文本正文，直接创建单个 `text` 消息段。
- 修改接口始终允许更新发送者、显示名称和来源。列表为每个现有 `text` 消息段返回原始索引与正文，WebUI 分段编辑；图片、视频、表情、市场表情和合并转发原样保留。
- 服务端必须要求提交的文字段索引与当前瓶子中的完整文字段索引集合一致，拒绝重复、缺失或过期索引，避免并发变化后覆盖错误消息段。
- 旧版单个 `content` 更新仅兼容纯文本瓶子；纯媒体瓶子没有可修改的文字内容，不能把媒体静默替换成文本。
- 存储更新必须在同一事务中同步 `bottles` 和 `bottle_threads` 的发送者与显示名称，否则后续所有权检查会使用旧值。
- 新增、修改和删除均写入操作记录；后台新增记录的 `actorId` 是当前管理员，而不是表单中填写的瓶子发送者。
- 响应式列表同时渲染桌面表格和移动列表，因此编辑表单和删除确认放在共同父级，避免隐藏视图产生重复表单、重复 ID 或重复请求。
